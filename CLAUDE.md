# CLAUDE.md

## Commands

Use `uv` for everything Python.

```bash
uv sync --extra dev --extra mobile --extra tui   # install; without --extra mobile ~40 phone-host tests skip silently, without --extra tui the terminal app's tests skip (add --extra pdf for Marker; manim is a core dependency)
uv run pytest                            # everything, both gates: about 2 h serial. Times: docs/reviews/refactor-a6.md
uv run pytest -n 8 --dist worksteal -m "not arc_close"   # the landing gate (pytest-xdist): about 12 min in a 10 GB scope
uv run pytest -n 8 --dist worksteal -m arc_close         # the arc-close gate: pre-registered sims and long journeys, about 7 min
uv run pytest -m "not slow"              # while iterating: leaves out long sims, journeys, renders and every arc_close test
uv run python scripts/affected_tests.py  # per-step gate: the test files a change's imports reach (or `tests`); pass them to pytest from bash
uv run python scripts/check_gate_partition.py          # the two gates together collect every test, once
uv run pytest -m durability              # production SQLite pragmas + WAL + fresh vaults, about 7 min serial (or add --durable-sqlite to any selection)
uv run pytest --fresh-connections        # production connection opens and fresh-schema builds in the fast lane
uv run pytest tests/test_scheduler.py::test_name -x   # single test
uv run lint-imports --no-cache           # architectural dependency contracts
uv run ruff check                        # bug-finding lint (rules in pyproject.toml); in every gate beside lint-imports
uv run learnloop --help                  # CLI; most subcommands take --vault and --json
uv run learnloop doctor --fix-state --vault <path>    # after manual vault edits
uv run learnloop config effective --vault <path>      # normalized effective config
uv run learnloop rebuild --shadow --json --vault <path> # isolated replay diff
uv run python -m learnloop_sidecar       # sidecar directly (JSON-RPC over stdio)
```

Desktop app (from `apps/learnloop-tauri/`):

```bash
npm install && npm run dev               # Tauri shell spawns the Python sidecar itself
LEARNLOOP_VAULT=/abs/path npm run dev    # open a specific vault (default: last-opened, then fixtures-local/*, then a new ~/LearnLoop)
npm run typecheck && npm test && npm run frontend:build   # npm test = vitest
cargo check --manifest-path src-tauri/Cargo.toml
```

Debug env vars: `LEARNLOOP_SIDECAR_LOG_LEVEL=DEBUG`, `LEARNLOOP_SIDECAR_DEBUG_LOG=<file>` (tees sidecar logs; Tauri can swallow stderr), `LEARNLOOP_SIDECAR_TIMEOUT_SECS` (desktop per-request timeout, default 960s), `LEARNLOOP_PYTHON` (pins the sidecar interpreter), `LEARNLOOP_AI_PROVIDER` (overrides serving AI routes, but not the explicit opt-in `embedding`, `field_question_classifier`, or `field_llm_probability` routes).

## Architecture

See `docs/learnloop-architecture-vault/Home.md` for information on architecture, examples of user journeys, and previous design decisions (ADRs in `Decisions/`; ADR-015 WAL + `synchronous=FULL` supersedes ADR-014). Changes to persisted meaning (scoring, scheduling, projections) follow `docs/algorithm-change-playbook.md`: a new tag is one constant in `algorithm_versions.py`, one row in the upgrade table (`src/learnloop/ops/upgrades.py`) and one test row (`tests/test_upgrades.py`). The table starts at `OLDEST_SUPPORTED`; a vault below it is refused everywhere and upgraded with the code at the git tag `pre-floor` (ADR-019). Feature specs are in `docs/specs/`.

The vault's generated notes (`Reference/Modules`, `Reference/Desktop`, `Reference/Database/Tables`, `Reference/Configuration/Fields` and their catalogs; `_scripts/{module,desktop,db}_generate*.py`) carry no commit of their own: `Reference/_generated.md` records, for each generator, the newest commit that changed a generator input when it last ran, and a generator rewrites only its own row. Regenerate after committing the source change (`_scripts/generate_all.py` runs all three), and commit every note that changes; a regeneration on a clean tree changes nothing.

## Tests

`tests/` is flat (~1,400 `test_*.py` files) with `conftest.py`, `helpers.py`, `structured_ai.py` (`StructuredClientFake` for AI doubles), and `openai_fakes.py` at the root. `helpers.py` has the vault-seeding builders — use them instead of hand-rolling a vault. A test file never imports another: what several files share (fixtures, builders, fakes, constants) lives in a helper module without the `test_` prefix (`tests/<topic>_helpers.py`, `*_fakes.py`), imported where it is used, so `scripts/affected_tests.py` follows only the imports a test needs; `tests/test_test_layout.py` fails on a new test-to-test import, and conftest rewrites the asserts in `tests/*_helpers.py` as in a test file.

`tests/test_identity_pins.py` fails when a compared identity (a cache, reuse or dedupe key, a manifest or version hash, a seed, a structured prompt that keys reuse) moves at a fixed input, when a type dumped whole into one changes shape, or when a new dump reaches a hash, seed, manifest or structured prompt unregistered (`tests/identity_pins_helpers.py`). Keep the bytes (a removed config field into `config/retired.py`'s `RETIRED_FIELDS`, `exclude_if` or an explicit identity view) or bump deliberately under `docs/algorithm-change-playbook.md` and regenerate in that commit with `python tests/test_identity_pins.py --write`, the reason in the landing note.

`conftest.py` does several things that surprise people. Each run's files (vaults, `tmp_path` roots, the isolated config dir) go in one `.pytest_tmp/run-<pid>-*` directory that the run deletes when it ends, and the next run removes those of killed runs (`tests/session_tmp.py`; `LEARNLOOP_KEEP_TEST_TMP=1` keeps it, marked `KEEP`, to inspect a failure: delete it yourself). It isolates `LEARNLOOP_CONFIG_DIR` from the developer's real `~/.config/learnloop/`. It monkeypatches `db.connection.connect` and `db.migrate.switch_to_wal` to disable SQLite durability and WAL, and makes `os.fsync` and the target of `db.copies` skip the disk (opt back in with `@pytest.mark.durability` or `--durable-sqlite`, which apply to fixtures of every scope — WAL behaviour is only testable there). `create_basic_vault` copies a per-session template instead of initializing (pass `fresh=True` when a test needs real init/migration; the durability lane also builds fresh), and a process's later fresh schemas are copies of its first real build. A test's `connect()` calls reuse idle connections (`tests/connection_reuse.py`, most of the speed-up from 59 minutes to under 20 at `-n 8`): a setting, DDL, a replaced file or a patched open path ends the reuse, and `@pytest.mark.fresh_connections` or `--fresh-connections` opens every connection for real. So a background job that used to lose a race with a slow main thread may now win it: a test must wait for the work it reads, not rely on timing. A reader holding a snapshot blocks a background commit in this lane's rollback journal, though not in WAL: a test that needs both at once belongs in the durability lane. Builtin outcome schemas get a fixed id per slug, because the id seeds the certainty bound's draws. The router's seeded draws are pinned by default (`tests/pinned_draws.py`): the mix's and the stop coin's seed, the numeric policy's, open pick's and the lesson suggestions' depend on the test's node id and the order of its distinct boundaries, the check day on the test's offset from its first date (that date stands for 2026-10-12), and the numeric policy runs one batch of draws, so a test on the objective path passes or fails the same way every run while still meeting stops, offers and checks where its fixed seeds land; a test that needs one arm still pins it (`RANDOMIZED_CHECKS_OFF`, the ih2 `draw` fixture, `never_stop_or_offer_draws`). `@pytest.mark.real_draws` gives a test production's seeds and refinement, for a test whose subject is the draw or a seed function; a process a test spawns calls `pin_this_process(label)` to pin its own, and a race with a background job is not a draw: wait for the job. Because of the connect patching, prefer `from learnloop.db.connection import connect` at module level in code under test. `--strict-markers` is on: declare new markers in `pyproject.toml`. Mark a test `slow` when it takes more than about 15 s after these shortcuts; the landing gate still runs it. Mark it `arc_close` instead only when it is a pre-registered simulation or a journey whose size is the point: only the arc-close gate runs it, and conftest makes it `slow` too. Anything else that is slow gets shrunk or split, and replay, durability and end-to-end journeys stay in the landing gate. `mixture_env`'s vaults roll the objective out 30 days, not the served 90 (`tests/router_mixture_helpers.py`; the `served_horizon` fixture keeps 90). `tests/cli_surface.json` pins each CLI command's parameter contracts: add nothing for a compatible addition, and edit it only for a deliberate incompatible change (`python tests/test_cli_help_snapshot.py --write`).

Adding a migration: classify each new table in `src/learnloop/db/table_roles.py` (a `DERIVED` table also needs exactly one replayer in `substrate/rebuild_orchestrator.py`; both are tested). Then upgrade `fixtures/migration_head/` in place: `learnloop.db.copies.backup_database` its `state.sqlite` to a scratch path outside the checkout, `apply_migrations` it under `upgrade_allowance(UPGRADE_SCRATCH_COPY)`, `PRAGMA wal_checkpoint(TRUNCATE)` and `PRAGMA journal_mode=DELETE`, then remove the tracked file and `backup_database` the copy into its place (rollback mode, no companion files, `integrity_check` ok), then add a section to the fixture's `README.md` naming the new head. Nothing is renamed and no test or script names the number: tests read `MIGRATION_HEAD_FIXTURE` and `migration_head()` from `tests/helpers.py`, the reference scripts read the head from `migrations/`, and `tests/test_migrations.py` alone checks the fixture holds it. A new table's objects still join the earlier migrations' "nothing else changed" upgrade diffs (their `*_ADDED_OBJECTS` sets). Then rerun `db_generate_reference.py` and `db_validate_reference.py`.

Since storage S0 (`docs/specs/spec_storage_sync_v1.md` §6.11) the public tip tracks no personal data: the owner's vaults (`linear_algebra`, `probability`, `arxiv_v2`, and the older `arxiv`, `conic-sections`, `law`, `physical_therapy`, `linear_algebra_legacy`) live outside every checkout (`~/learnloop-vaults/<name>`; retired ones in `~/learnloop-retired/`), the textbooks in `~/learnloop-books/`. Never search the filesystem for them. Tests that read them carry the `owner_vaults` marker and are skipped unless `LEARNLOOP_OWNER_VAULTS=<dir>` names backup-API copies under their old fixture names (`tests/owner_vaults.py`; make the copies with `learnloop.db.copies.copy_tree_with_databases` under gitignored `fixtures-local/`; never point it at a live vault); fixture walkers walk only what git tracks. The only tracked databases are `fixtures/migration_head/state.sqlite` (sanitized, with a project-authored transcript and answers by `scripts/sanitize_migration_head_fixture.py`; rebuild it from the tracked copy so the sanitized text carries over) and the synthetic `fixtures/mvp017_route_check_replay/state.sqlite`, both in rollback mode. `tests/test_public_tip_guards.py` (G8) fails on any other tracked database, a PDF/EPUB/DjVu/audio/video file outside `samples/` (each needs a `samples/NOTICE` entry), another binary outside `docs/` images and `apps/` assets, a file over 5 MB, a `canonical-sources/` file outside those two fixtures, or a git-LFS rule; a screenshot showing a book page goes on `docs/screenshots/BOOK_PAGES.md`. A commit that untracks paths deletes their clean copies in any checkout updated to it: the owner lands such commits (S0's own through `scripts/s0_landing.py`, which refuses until the data is copied out), never an agent. Empty `-wal`/`-shm` beside a fixture are harmless; a non-empty `-wal` fails `test_tracked_fixture_databases.py` (checkpoint it, never delete it), and conftest fails the run if a test changed a tracked fixture's or an owner-lane copy's journal header or left WAL frames. Copy databases with `learnloop.db.copies` (backup API); a new `shutil` copy call fails `test_sqlite_file_copies.py` until audited there.
