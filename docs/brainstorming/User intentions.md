
The intent of this application is to have memory and skill be a choice. 
There's 2 main journeys for Learnloop--we want to be able to learn something, and we want to be able to retain it.  I want to choose which knowledge and capabilities become a dependable part of what I can do. LearnLoop should help me understand them, use them, and keep them available—at the depth and attention cost I choose.

Learnloop should schedule repeated engagement with knowledge (as opposed to repeated presentation of the same questions).

I want to be able to add anything to learnloop as a card that I want to remember--math problems I see that are difficult to me, concepts from machine learning that describe how my projects work, concepts from arxiv papers that I want to understand fully and remember, etc.  This process should remove as much clerical friction as possible while preserving the effort that actaully produces understanding.

For example, I want to be sure I can explain my latest project about making a GRU model for gesture control. I want to be able to answer questions like "why was this architectural decision made, and what would happen if you did this instead", or  "what does this part do", "explain each layer of this step by step", "explain the more challenging aspects of this". Another example is within an arxiv paper "explain why the authors made this decision for this equation", "explain each part of this diagram", "why is this paper novel and what does it imply about future work", or "teach me the concept described in this paper" and "what sort of assumptions does this paper make about its domain"? For specific math problems, I want to be able to recall the entire solution from its first step to its last step via cold retrieval.  I want to be able to transfer the concepts to other similar problems instead of having a fragile brittle memorization of the solution. I want knowledge to become available when the situation calls for it, even when nobody tells me which concept to retrieve ("heres a new problem, which approach is appropriate and why?"). I want to be able to explain the solution and answer difficult follow up questions like in Learnloop's teachback feature. Completeness within this context is to mean observable capability within a chosen scope-- so "understanding narrow idea deeply" doesn't imply "expanding its scope forever" if not chosen to do so. Reaching an agreed atrget should alow maintenance, closure or an explicitly chosen next step. 

When something is added (that is, I find something new that I want to retain and learn completely), a daily queue should present to me what to do in order to keep up my memory and to further my understanding or push my boundaries. I think over time it might become unwieldy if every concept was vying for my attention to push my boundaries, so there might be things I want to learn in its entirety and some things I want to just keep/maintain knowledge of. This intent should be communicated to the daily queue.  
For more narrow scope concepts like this, I should be able to fully understand these concepts and be able to teach it back. I should be able to think through counterfactuals like what if assumption x, y, z was changed, or what implicit assumptions was I making or the author making when approaching this problem? 

The other main intent in Learnloop is to be able to take a canonical source and be able to turn it into questions and cards via what sort of questions I asked the tutor while reading, what I'm weak in, and what the textbook proposes. I want to be able to go through canonical sources and fully extract the knowledge from them and be able to use them fully.   

For these intentions, we want it to be as easy as possible to maintain knowledge and acquire knowledge. We want errors and misconceptions to be caught as early as possible and corrected. We want the user to not be under delusions of how skilled they are in something, but be able to adapt quickly to the user's skill without overburdening them with too much friction via tons of lengthy questions. We want optimal learning through immediate and cold retrieval subject to the constraints of minimizing avoidable diagnostic and coordination effort, future maintenance obligation, frustration and learner time. This implies probing when resolving uncertainty could change the next intervention. Obviously a decent amount of practice is needed to become skilled, but there is a lot of inefficiency in traditional learning where time is spent trying to identify why a mistake was made and what should be done to  remediate it and ensure it doesn't happen again. 

In this way, an attention budget is needed. Learnloop could serve me a few really complex question that has me think very deeply and refreshes all my understanding and connects many concepts I want to know/learn/keep together, then an additional few questions to repair a weak point or apply it/push my boundaries. 

Learnloop also should be able to allow the user to grow--after enough practice, maybe Learnloop can ask me to design a test of my own hypothesis, or ask me which additional evidence I would need to make a decision. 

I think a longer-scope idea for Learnloop would also to be support authentic project-driven learning via a Quest feature. Going back to a side project with gesture control, I might want to understand GRUs because a specific model is failing to perform well. A more traditional application would identify the topic, teach what a GRU is, then test whether I understand it. But with Learnloop, we could start with the actual problem as to why the model might be failing in the project context. Then through this project context maybe we could reason through competing explanations, identifying the relevant concepts, choose a discriminating experiment, understand the result and propose revisions. 

Instead of always scheduling things for later, we could reccoemnd applying an idea in an active task immediately. 

There's many different types of understanding for a given concept, and perhaps we could specify in natural language which capabilities matter for my given Quest commitment (recall, explain, reconstruct by indepently deriving a solution/procedure, transfer to fresh problem with meaningful structural differences, predict consequences of changing assumptions or params, teach/defend)

To summarize, I think Learnloop should be able to act as a way to not get left behind in this world where new advancements are constantly being made and loss of understanding of your own projects can be easy with AI generated code. It should be the best way to learn a textbook's concepts cover-to-cover and be able to apply them robustly. It should be a great way to prepare for technical interviews, especially questions that ask about explaining your own projects and be able to answer follow up questions easily. It should be a means, if given the time, the most efficient path or the gradient of learning to be competitive in the concepts you so choose is frictionless (as much as it can be).
