## What changed, per finding

- **F1.** `prefetch._ask` takes a `revalidate` callable and calls it before every physical judge request (one `route.ask` is one request: `SpendCaps.max_retries = 0`). Section mode reads the section's blocks again under the protection as it is now (`withheld_message` and the items' protection) and compares the content hash the saved prompt was built from; gap mode checks the passage again. A change discards the saved context: `JudgeUnavailable("protection_changed")`, nothing more is sent, nothing is decided.
- **F2.** The durable rich worker (`rich.run_rich_job`, `build_mode` prefetch) checks, when it starts and in its gate's hold before every request and before it stores, that `figure_rich_author` resolves to a subscription route as configured now (`PREFETCH_NOT_PLAN`), with the injected client's own billing in tests. A quick prebuild's gate holds likewise on `figure_author` (`service._prefetch_build_hold`, `PREFETCH_AUTHOR_NOT_PLAN`). `run_builds` rechecks the author route before each build and takes the rich spawner per build. These holds count as background stops (`figures_changed`), never as held-out material.
- **F3.** `resume_rich_intents` keeps a prebuild's intent `build_mode = "prefetch"` and starts nothing while `background_hold` refuses (switch off, battery, foreground work), so the worker applies every P5 condition (F2, F6, F7 included) and the render keeps its background treatment.
- **F4.** `prefetch.item_protection` covers every passage (`item_exclusions`) of an item under a live administration: an open cold check, a repair's cold retry, a live assessment reservation, or a diagnostic probe. These are `learner_protection.withheld_items`' `cold`, `reserved` and `probe` reasons, the one authority, outside today's plan too. It also covers the stored plan's unresolved items. It applies before judging (section blocks; a gap's passage) and to the author's whole context (`context_spans`: `service.source_context`, the passage and its neighbours), and it is read again before each build. Unreadable protection prebuilds nothing (fail closed).
- **F5.** `pending_builds` also takes `deferred_power` and `deferred_plan` rows whose horizon is open (`PL.BUILD_DECISIONS`). The row keeps what was decided then; its build sets `request_id` (set once). A built deferral is an observation of opening like a `build` row (the draw said build and the cue was there); the report's `built` counts it.
- **F6.** The daily build cap is spent when a build starts. `reserve_build` works under a process lock: today's prefetch request rows (durable, a resumed decision of an earlier day included), plus the decisions started in this process and not yet stored. Decide-time `capped` uses the same count. The render-minutes cap is enforced in the rich worker, when the job starts and before each request, from actual render time (`PL.render_minutes_left`). Renders are one at a time (`RENDER_CONCURRENCY`), so at most one is outstanding.
- **F7.** `background_hold` also yields to foreground work. The pass's gate holds on it before every judge and quick-build request, and the rich job's hold waits for foreground work to end (up to `FOREGROUND_WAIT_SECONDS`, moved to `figures/foreground.py` and registered there) before each of its requests. The judge is admitted only when idle and with no prebuild rich job in flight (cached judgments otherwise). A prebuild's rich job in flight holds the next prebuild (one pipeline at a time), its batch takes the default priority band below pressed figures, and a pressed rich job marks itself foreground work while it runs. A render already running continues, niced (holds are checked between requests, never inside a render).
- **F8.** `planned_visual(node)`: only a node that carries a planned `visual` is a lesson candidate. TE1's `PlanNodeV1` has none, so with TE1's real plans the trigger builds nothing. The new test opens a lesson through TE1's accepted `write_plan`. The stored-node `visual` shape stays covered by `test_lesson_trigger_builds_the_planned_visuals_of_nodes_not_yet_reached`. **Scope:** adding `visual` to `write_plan` and referring to it by node id in the turn that reaches the node is RW5d P4b's work (in flight in `learnanything-merge2`, teacher visuals through the figure service). P5 takes `visual.goal_text` once P4b's nodes carry it, and P4b's landing should check that the request it delivers is byte-identical, so the input hash is reused.
- **F9.** `horizon_at` returns the horizon's instant. For a plan it is the end of the plan's local day, or its completion. For a section it is `completed_at`, and for a lesson `closed_at`. For an offer it is the end of the reading session it was made in (RW6b's session digest spanning it) or the end of its local day, whichever is first. For a gap it is the next plan's creation, or the moment it is first seen closed. `opened` and `asked` read only events in `[created_at, horizon]` (parsed timestamps, never string order), and `asked` matches the same request identity: the same passage (exact spans) and the same goal (none for anchor-only).
- **F10.** `rich_pending` never lists a prefetch rich job (no building, waiting or failed line, switch on or off). An unpressed prebuilt figure lists only when it is shown (completed and verified), never failed or unsupported. A press of the same input is its own request with its own line.
- **F11.** `reader.figures` carries `prefetch_pending: true` (absent otherwise, and always absent with the switch off). It is true while a decision to build for this source has no request yet (deferred ones only on mains, so the Reader never polls on battery) or a prebuild's rich job for it is queued or running. `useFigures` reads the figures again at `RICH_POLL_MS` while it is true and stops when it clears, with no toast and no focus move. Unpressed prebuilt lines take their place in the cue budget: per section, at most `[cues] density`'s budget, the earliest built first, none with cues off; a pressed one is never cut. **Scope:** the cut shares the density budget per section without subtracting that section's margin marks, which the Reader's rail computes from the plan on a separate read. Recorded as an open item.
- **F12.** `linux_power_state` establishes mains only from a complete inventory. No `power_supply` directory, an unreadable one, a supply whose `type` can't be read, or a battery whose `status` can't be read is `unknown`, which counts as on battery. An empty, readable directory (a desktop: this machine, carson, lists none) is mains.
- **F13.** `judge_gap` appends one `judgment_ledger` row (task `figure_prefetch_judge`, `left_kind` learner_gap, `right_kind` reader_span) keyed by the input hash (gap, passage and the context sent) and the prompt version, with the model, the goal and `p_open`. A repeated input reads it back with no call.
- **F14.** The pause logistic's load (`PausePosterior.load`, `plan_load`) is the day's requests with the known tokens in them. A request that reported tokens counts as its tokens over the measured mean tokens per reporting request, and a request that reported none counts as one average request (explicit missingness). With no tokens reported anywhere, the load is the requests. A build's expected requests are measured (`PL.incremental`: figure-author calls per authored request, rich-author calls per rich job), mixed by the trigger kind's measured rich share (else the pressed share); unmeasured, the structural minimum of one call. No new prior: the existing slope prior is per standardized unit of load.
- **F15.** `figures.prefetch_enabled` defaults to **on** (Q21; the owner's standing decision of 2026-10-12 accepts every spec's recommended defaults). The 32 defaults snapshots were recomputed with `defaults_fingerprint_for_version`, and a second pass changed none. The P5 checkpoint (a week on the desktop with the report's `prefetch` block) stays an owner item and may turn it off. The suite sets `LEARNLOOP_FIGURE_PREFETCH=off`, as it sets `LEARNLOOP_APPROACH_MAP_BUILDS`: a hook queues nothing unless the test injected the runtime's seams (`ctx.figure_prefetch_inline`), so no test starts a background pass by accident.

What changed:

- **F1.** `PrefetchEnv.loaded_now()` gives the environment over `current_vault()` (the sidecar's loaded vault), or None when it can't be read. Both judges' `revalidate` reads the item protection, the section's blocks and `withheld_message` from it before every physical request; None fails closed (`protection_changed`, nothing sent). `run_builds` also reads the item protection from the vault it already re-read for the switch (it read `env.vault` before), so a build's last check uses the same snapshot as its switch check.
- **F16.** `FiguresGate` takes an optional `wait()`, run at each check before the gate reads the vault. A prebuild's rich job passes `_prefetch_wait` (wait up to `FOREGROUND_WAIT_SECONDS` for foreground work), and its hold no longer waits. So the whole gate (root, `figures.enabled`, the key, and the hold: switch, power, plan route, render minutes) is decided on the configuration read after the wait. The job's start check is now `gate.check("prebuild")`, which follows the same path. If foreground work is still running after the wait, the hold yields as before. Other gates are unchanged (`wait` defaults to None).
- **F17.** `service.prefetch_plan_waits(vault, repository, extraction_id)` finds this source's prebuild rich jobs that are waiting for the plan. It takes the newest job per input (a newer press or prebuild of the same input speaks for it) and returns them only while figures ahead of need are on, the machine is on mains and the passage is not held out. `reader.figures` passes them to `_retry_plan_waits` along with the visible lines, so the per-job `due_for_plan_retry` interval still applies. They still list no line (F10), and the requeued job's own gate checks everything again before any request.
- **F18.** `prefetch_pending(..., pass_running=False)` returns False on battery and with the switch off. An unstarted decision counts only while the context's prefetch pass is running now (`PrefetchRuntime.running()`, through `prefetch_runtime.pass_running(ctx)`; the drain builds waiting decisions first). Otherwise it waits for the next trigger, and a read does not fire one. A prebuild's rich job counts only while it is queued or running; one waiting for the plan is retried by the read (F17). The Reader also stops its prefetch-driven reads after `PREFETCH_POLL_LIFETIME_MS` (20 minutes) per open source; reopening the source starts afresh. This is a UI pacing bound (two foreground waits), not a model or decision parameter, so it has no registry entry. The F11 test now marks a pass running before it expects `prefetchPending` for an unstarted decision.
