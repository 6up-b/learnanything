## How the list was made, and its limits

- **Sites.** Every string constant and f-string in `src/` (`learnloop`, `learnloop_sidecar`, `learnloop_mobile`, `learnloop_mcp`). Docstrings are excluded. Names in f-strings resolve to module-level string constants, across modules when the name is bound to one table everywhere. A table passed to a helper whose own SQL takes the table from a parameter (`_insert(connection, "t", ...)`, `rows(connection, T)`) counts as that helper's write or read. A string that's exactly a table's name is a dynamic reader (`find_record`'s list), unless it sits beside SQL on the same table in the same function (a guard) or in a list file: the role registry, AD's two guard registers, debug time's timestamp list, doctor's lists. SQL built from other variables is missed.
- **Reached** means name reachability, not import reachability. Seeds are names used at module or class level (registries, `METHOD_REGISTRY`, Typer decorators, `__all__`), every decorated function and every dunder. A reached function reaches every function whose name it mentions, as a name, an attribute or an identifier-like string. Name collisions make this over-approximate, so "unreached" is a strong claim and "reached" a weak one. Tests aren't scanned, so a function only tests call is unreached. Frontend callers reach the backend through `METHOD_REGISTRY`'s module-level strings, so they're covered by the seeds.
- **Replayer / upgrade:** a `DerivedStateReplayer` that owns the table, the per-LO replay reset, any other rebuild-file use, and the `*_upgrade` modules that name it.
- **Feature:** the first migration that creates the table. **FK children** come from the migrations applied to an in-memory database.
- **Tolerates absence** reads the reader's own function and the functions enclosing it, looking for a `sqlite_master` query, a `*table_exists` / `*table_present` / `has_table(s)` / `_table` call, `PRAGMA table_info`, or an `OperationalError` handler. A guard in a caller is missed, so "no" can be wrong; "yes" means a guard was seen. Over all 397: 16 yes, 163 partly, 202 no, 16 with no reader. Dropping a table whose readers say "no" needs those readers gone first, which J2-J4's order already requires.
- **Classes are from code alone.** A runtime gate (a config switch, a vault kind) doesn't make a reached writer unreached; group C is where that matters.
