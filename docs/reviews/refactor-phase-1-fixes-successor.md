## 3. Design questions (not decided here)

- **Q1 (S1's remainder).** The update's facet set, the `tau_facet_share` filter and `candidate_facet_support` read today's item. The contract freezes criterion targets but no facet weights; the attempt row records `evidence_facets_json` and `evidence_weights_json` at answer time. Choices: (a) leave them on today's item, as the attempt pipeline's mastery coverage does (an author's weight edit then moves rebuilt uncertainty and mastery alike); (b) read the recorded facets and weights on replay for the uncertainty layer only; (c) do (b) for the whole attempt pipeline (a larger change of meaning, mastery included). Recommendation: (b) under the same predicate if the owner wants the uncertainty layer fully frozen; it is a contained change in `attempts` and `build_facet_uncertainty_updates`.
- **Q2 (S4).** A full-marks answer of a massless attempt type (`guided_walkthrough`, mass 0 by default) still does not end the streak, while a massless failure still counts toward it. Choices: count both, count neither, or keep (landed). Recommendation: count neither (a walked-through answer is no independent evidence either way), as its own successor if wanted; not taken here because the row names only the zero discount.
