# Refactor D2a: the default test vault moves to the head

Step D2a of arc D (`docs/specs/refactor_strategy_v3.md` §2.6), on branch `refactor/d2a-head-test-vault`, based on main `2bc93d4d2b` (arc C closed, K0 identity pins and the K1/K2 reviews landed). Finding 3 of the strategy: `AlgorithmsConfig.algorithm_version` defaults to `mvp-0.6` and `create_basic_vault` pinned it, so most basic-vault tests ran a path below every real vault's tag.

Rules held: no change under `src/`; `config/schema.py`'s default is untouched (D1's); no live model call; no migration; no identity pin moved (`tests/test_identity_pins.py` passes unchanged: no pin's fixed input comes from `create_basic_vault`, so none needed keeping at its old tag).

Why the facet registry: from `mvp-0.7` (KM2) an item's evidence facets are registry entries. On a head basic vault with the old empty registry, `run_doctor` reports `evidence_facet:empty_registry` (error) for `pi_svd_define_001`, and patch application refuses items naming unregistered facets. `learnloop init` plus the KM2 authoring path would have registered it, so the head basic vault does too. A consequence the tests show: the registered `recall` facet is a real vault entity, so fixtures that count facets (embedding backfill, graph nomination) now replace the registry rather than add to it.

Not changed: `create_placement_vault` (`mvp-0.11`) and `create_daily_plan_vault` (`mvp-0.14`) already pin explicit tags of their own (117 test files use them), as do `source_set_synthesis_helpers._setup(mvp07=False)` and `split_live_helpers.split_vault` (its `version`). Those are explicit old-tag pins, D2b's batch, not the silent default this step removes. One side effect of `split_vault` (about 100 importers): it seeds its history at the basic vault's tag, now the head, and only then sets its explicit `version`; see §7.

## 4. Findings

Head-path behaviour that looks wrong. No production code changed; each is a strict xfail asserting the right behaviour, named `D2a finding:` in its reason, so it goes red when fixed.

1. **A success never resets a facet's failure streak** (`test_recall_coverage_interventions::test_success_resets_repeat_failure_gate_and_coverage_is_not_failed`). In `substrate/canonical_projection.py`, the `consecutive_failures = 0` reset sits inside the failure-mass loop, after `if negative_fraction <= 0 ...: continue`, so a full-marks answer skips it. After two don't-knows and a correct answer the canonical row keeps 2 and `repeated_facet_failure` stays 2.0 (the item streak resets). Derived state: a rebuild re-projects it the same way; no ledger damage. Checked by reading the code.
2. **Every model grade naming a KM4 mechanism type files a "new error type" proposal** (`test_codex_attempt_flow::test_codex_recall_wording_uses_recall_failure_not_new_error_type`). `diagnosis/error_taxonomy.persist_unknown_error_type_proposals` treats `vault.error_types | BUILTIN_ERROR_TYPES` as known, and `BUILTIN_ERROR_TYPES` is the `mvp-0.6` vocabulary; the head's validated attributions carry mechanism names (`retrieval_failure`, `conceptual_schema_error`), so each grading adds a pending proposal (deduplicated into the waiting batch, but never empty). Checked by reading the code.
3. **`teach_back.transfer_evidence_multiplier` doesn't reach the head's belief** (`test_teach_back::test_transfer_tier_evidence_mass_is_discounted_symmetrically`). A transfer-tier criterion adds the same canonical facet mass as a core one. Either the setting is dead at the head or the projection lost it.
4. **A targeted error attribution's facet outcome doesn't reach the head's belief** (`test_deferred_regrade::test_deferred_regrade_replays_targeted_error_attribution_facets`). The attempt's `facet_outcomes` names `numeric` at 0.0, and the canonical projection gives `numeric` no state (registered facet, valid registry). It may be KM's design (the projection reads criterion observations only), in which case targeting has no effect on belief; the owner should say which.

Head-path facts that aren't bugs but make tests vacuous or code unreachable (recorded, not xfailed):

5. **The follow-up slate's facet-EIG ranking never runs at the head.** `learner/facet_state_reader.facet_uncertainty_states_for_lo` returns `[]` on every canonical-state vault (a named KM4 seam), so `select_followup` ranks every candidate by the fallback overlap and `predictive_eig_weight` never acts. `test_predictive_eig` is pinned; the same seam explains the facet-uncertainty pins in groups A, B and D. Candidates for D6/D7's dead-at-head list.
6. **The planted-type probe simulation returns an empty report at the head, silently.** `sim.diagnostic_validation.run_probe_validation` needs the opening episode (gone at `mvp-0.11`) and parametric instances (gone at `mvp-0.45`), so `ValidationReport.passes()` was vacuously true on a head vault. Its helper is pinned and `test_planted_types_pass_the_checkpoint_gate` now asserts a non-empty report.

No failure showed the head path corrupting persisted data.
