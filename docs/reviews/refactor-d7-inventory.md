## 0. What is counted, and how

**What counts as a kill switch.** A config field, boolean or mode, whose documented purpose is to turn a newer behaviour off and restore its predecessor. There are two kinds:

- **Tagged (§1).** The switch of an algorithm successor `mvp-0.N`. It is named in that tag's comment in `algorithm_versions.py:46-936`, or in the field's own documentation, or it is gated by a successor's tag predicate in `router_objective_switches.py`. These are D7's subject. The rule proposed for D7 is "a switch goes when every vault is past its tag and no vault sets it" (strategy §2.6 D7). That rule can only apply to a switch that has a tag.
- **Untagged (§6).** A live change shipped behind a switch with no successor tag, whose documentation says the off value restores the previous behaviour exactly. The proposed rule cannot apply to these, because there is no tag to be past. They are listed so the count is complete.

Every other boolean or mode leaf of `LearnLoopConfig` is counted by kind in §6's census: feature opt-ins, cost controls, and operational, display and selection settings. Together, §1 and §6 cover every such leaf.

**Where the fields come from.** An AST walk of `LearnLoopConfig` (`config/schema.py`, 5,104 lines) at this tip lists every leaf with its default: 876 leaves. Of these, 279 are booleans and 36 are string or `Literal` modes. The walk ran under the empty-home wrapper and imports only the config models. Of the 315 booleans and modes, §1 covers 97 and §6 covers the other 218: 54 untagged kill switches and 164 other settings.

§1 has 99 rows, because two of its fields are floats rather than booleans or modes: the router objective's rates `stop_coin` and `pick_open_share` (§1.5). §1 also keeps two fields that are not tagged switches, for reference: `router_objective.receipts` (RO0's logging switch) and `facet_diagnostic.canonical_belief_fixes` (the head's switch). One tag's switch lives outside `learnloop.toml`: the phone host's `phone_probes` (mvp-0.54, `src/learnloop_mobile/config.py:32`). It is noted in §1.6 and not counted.

## 1. The tagged switches

**Columns.**
- **tag:** the tag the switch serves past. Every tag here is at or below the floor (`mvp-0.58`) unless the row says otherwise.
- **off code:** the code that is reached only with the switch off, given as ≈ lines in N files. "0" means an early return or a skip, so only the predicate and its plumbing go.
- **readers:** the predicate (file:line of the read) and its number of callers.
- **identity:** what the field's value enters beyond the whole-config digest of §0, which every row has and `RETIRED_FIELDS` holds.
- **persisted:** whether the off value changes rows that replay or `learnloop rebuild` derive projections from, or whether replay itself reads the switch. "serving" means it changes only what is served, displayed or written as workflow state or receipts.
- **tests:** off-only test functions; "port" counts tests that set the switch off for another purpose.
- **VR:** whether `scripts/vault_report.py`'s `D7_SWITCHES` names the key.

Notes:
- **`diagnosis.split_enabled`.** This is the largest single removal in §1.1.
  - **Porting:** about 18 tests use the switch only to make a joint-graded attempt to regrade or replay. They need a builder that writes one; several also pass `version="mvp-0.9"`.
  - **What stays:** placement keeps reading existing `split_held_at` stamps (`placement/state.py:888-893`).
  - **Cost:** the diagnoser has its own spend cap (`diagnosis.max_calls_per_day`, `config/schema.py:1995`), so this switch is not the only cost valve.
- **Getattr defaults of False.** Two predicates read a missing field as off although its schema default is on: `fold_follows_attach` (`attempts/hint_fold.py:239`) and `claim_fixes_live` (`learner/mastery.py:183`). So does `decision_active(None)` (`serve_eligibility.py:984-986`). A removal that leaves any of these predicates in place while dropping its field would silently serve the predecessor. Each must become a constant or go.
- **`mastery.claim_fixes_enabled` is read by replay and nothing records it.** A vault rebuilt with it off, after the field is gone, gets new mastery rows for LOs with covering claims at its next replay, with no doctor warning (`ops/doctor.py:1641-1705` checks only `projection_switches`' keys).
