**Canonical ingestion, interruption recovery, budgets, and cache review — September 6, 2026**

Preserving useful background work across app and sidecar restarts is the intended behavior. I have withdrawn the process-survival defect and blanket process-tree termination recommendation from the [original review](2026-09-06-refactor-review.md). The remaining requirement is to reconnect to identifiable work, preserve paid results, and prevent an expired worker from publishing over its replacement.

The largest opportunities are durable checkpoints at each model-call boundary, ownership checks when publishing, a single retry policy, and prompts with their reusable content first. The existing study-map shard cache and candidate revalidation are good foundations. The legacy canonical ingester has substantially weaker recovery guarantees.

Scope: HEAD `263a2a7`, including the canonical/v2-lite path, inventory execution, study-map synthesis, durable queue, OpenRouter-compatible transport, Codex SDK transport, and legacy Codex HTTP adapter. This follow-up includes retained defects: the baseline `d0f25b2` already contains the parallel lane persistence pattern, synthesis budget loop, legacy context hash, and nested chat retries. They should not all be attributed to the refactoring agent. No production code was changed; probes used disposable databases and fake providers.

**Findings, ordered by impact**

1. **[P1] A surviving worker can overwrite the replacement worker's completed result.** [ingest_queue.py:418](/home/saturn/Documents/thinking/learnanything/src/learnloop/db/stores/ingest_queue.py:418), [runner.py:501](/home/saturn/Documents/thinking/learnanything/src/learnloop/content/pipeline/runner.py:501). Completion updates by job ID without checking worker identity, running status, or attempt generation. Heartbeats check the worker ID but do not report lost ownership to the handler. I claimed a job as A, expired/recovered its lease, resumed and completed attempt 2 as B, then delivered A's completion. The row retained `attempt_count=2` but its result was replaced with A's older output. This extends finding 4 of the original review beyond the recovery SELECT/UPDATE race. Require conditional recovery and completion, and fence artifact publication using the claimed attempt generation. An old worker may preserve its output as an uncommitted candidate, but must not change the current job's result, apply proposals, or unblock dependents after losing ownership.

2. **[P2] Restarting before a dead worker's lease expires can leave its job permanently running in that sidecar session.** [jobs.py:2466](/home/saturn/Documents/thinking/learnanything/src/learnloop/content/pipeline/jobs.py:2466), [jobs.py:3198](/home/saturn/Documents/thinking/learnanything/src/learnloop/content/pipeline/jobs.py:3198), [runner.py:601](/home/saturn/Documents/thinking/learnanything/src/learnloop/content/pipeline/runner.py:601). Recovery runs on the initial bind, but normal draining does not repeat it; resume requeues failed/blocked/cancelled jobs, not running jobs. In a fake-clock probe, the new host bound 30 seconds after the dead owner's last heartbeat, correctly left the lease alone, and still left the job running after 180 seconds and a drain/resume. Add periodic, conditional stale-lease reconciliation and refresh the affected batches. A surviving worker that continues heartbeating must remain untouched. A dead worker should become visibly interrupted without requiring another app restart.

3. **[P2] Parallel inventory discards successful paid work when any lane fails.** [jobs.py:1148](/home/saturn/Documents/thinking/learnanything/src/learnloop/content/pipeline/jobs.py:1148), [jobs.py:1211](/home/saturn/Documents/thinking/learnanything/src/learnloop/content/pipeline/jobs.py:1211), [source_unit_inventory.py:669](/home/saturn/Documents/thinking/learnanything/src/learnloop/content/synthesis/source_unit_inventory.py:669). Each lane accumulates its results in memory; persistence begins only after every lane finishes successfully. With three units and two workers, I allowed two units to succeed and failed the third: zero inventories were persisted, job usage was null, and resume called all three units again. Within a multi-window unit, a later failed window likewise loses earlier results. The executor also waits for its running lanes when unwinding before the outer exception handler interrupts them, allowing additional work after the first failure. Deliver completed window/unit results to the existing runner-thread writer immediately, save their usage with them, and stop scheduling fresh work after failure or explicit cancellation. Keep deterministic output ordering independent of completion order.

4. **[P2] The synthesis input ceiling can be exceeded, and stage output budgets do not constrain provider generation.** [source_set_synthesis.py:2031](/home/saturn/Documents/thinking/learnanything/src/learnloop/content/synthesis/source_set_synthesis.py:2031), [source_set_synthesis.py:2057](/home/saturn/Documents/thinking/learnanything/src/learnloop/content/synthesis/source_set_synthesis.py:2057), [transport.py:24](/home/saturn/Documents/thinking/learnanything/src/learnloop/ai/transport.py:24). Preflight reserves only the initial shard inputs. An early evidence follow-up can consume budget needed by later shards, whose ordinary first calls have no cumulative check. A two-shard probe completed three calls and reported an input estimate of **322 against a ceiling of 260**. This violates even the code's own estimate; actual request cost is less constrained because estimates omit task instructions, schema, shared context, and repair/retry work. `StructuredRequest` carries no output limit, and chat sends the profile-wide `max_tokens`, while stage output limits are checked after generation. Reserve remaining work before each call, propagate supported per-request generation limits, and distinguish context capacity, generated-token allowance, artifact-size validation, and cumulative spend. Cached input still occupies context. Preserve oversized outputs for revalidation under revised limits instead of forcing identical regeneration.

5. **[P2] Two retry owners multiply one failed OpenRouter operation into nine HTTP requests.** [openai_chat.py:66](/home/saturn/Documents/thinking/learnanything/src/learnloop/ai/providers/openai_chat.py:66), [openai_chat.py:204](/home/saturn/Documents/thinking/learnanything/src/learnloop/ai/providers/openai_chat.py:204). The installed OpenAI SDK defaults to two retries; LearnLoop wraps it in three attempts of its own. With the real SDK and a mock HTTP transport returning 429, one completion made nine HTTP requests. Nine rejected requests do not imply nine billed generations, but the multiplication increases backoff, latency, and exposure to ambiguous provider outcomes. Choose one retry owner and an overall deadline; if LearnLoop owns the policy, explicitly disable SDK retries. Retain jitter and `Retry-After`, and persist the retry classification. OpenRouter documents server-suggested backoff and distinguishes request errors from errors that occur after generation starts. [OpenRouter error handling](https://openrouter.ai/docs/api_reference/errors-and-debugging).

6. **[P2] Truncated generation is handled as ordinary JSON repair with the same output cap.** [openai_chat.py:154](/home/saturn/Documents/thinking/learnanything/src/learnloop/ai/providers/openai_chat.py:154), [openai_chat.py:193](/home/saturn/Documents/thinking/learnanything/src/learnloop/ai/providers/openai_chat.py:193). The adapter ignores `finish_reason` and repairs a malformed fragment using the fragment and schema, without the original source context. A `finish_reason="length"` probe triggered a second request with the same 100-token cap and no original context. A syntactically valid repair can therefore delete missing content instead of recovering it; downstream gates may reject it after another paid call. Detect truncation separately, retain the partial response, and choose a smaller semantic window or a larger supported output allocation. Bound repair to genuinely repairable formatting/schema defects; require semantic gates before accepting a repaired artifact.

7. **[P2] Reusing a completed synthesis skips a newly requested apply step.** [source_set_synthesis.py:1546](/home/saturn/Documents/thinking/learnanything/src/learnloop/content/synthesis/source_set_synthesis.py:1546), [source_set_synthesis.py:1640](/home/saturn/Documents/thinking/learnanything/src/learnloop/content/synthesis/source_set_synthesis.py:1640). The cache returns before optional application. I generated with `apply=False`, then repeated the same request with `apply=True`: the result reused the proposal, remained unapplied, and made no second model call. Generation is also marked completed before application, leaving a related recovery gap if application fails before changing the manifest inputs. Separate generation, validation, application, and goal wiring into resumable phases. A valid cached proposal should satisfy the generation phase and continue the requested remaining work. The append path has the same early-return shape at [source_append.py:244](/home/saturn/Documents/thinking/learnanything/src/learnloop/content/synthesis/source_append.py:244).

8. **[P2] Legacy canonical reuse ignores changes to user instructions and other decision inputs.** [source_ingestion.py:244](/home/saturn/Documents/thinking/learnanything/src/learnloop/content/pipeline/source_ingestion.py:244), [source_ingestion.py:911](/home/saturn/Documents/thinking/learnanything/src/learnloop/content/pipeline/source_ingestion.py:911). Its context hash contains URI, content hash, source kind, and target learning-object IDs. It excludes instructions, subject context, prompt version, and provider/model identity even though those can change the requested output. Changing “Focus on eigenvalues” to “Focus on geometric intuition” returned the same proposal with one total model call. Freeze the effective generation inputs into a versioned request manifest and key reuse against that. Keep requested application/goal phases separate. Avoid naively hashing the latest mutable vault state on every retry, since the ingest's own changes can then invalidate its checkpoint.

9. **[P2] The legacy Codex HTTP adapter uses the health-check timeout for generation.** [codex_http.py:115](/home/saturn/Documents/thinking/learnanything/src/learnloop/ai/providers/codex_http.py:115). A generation configured for 180 seconds passed `timeout=5` to `urlopen`, taken from `healthcheck_timeout_seconds`. Slow canonical-ingest responses can consequently time out while the server continues working. Use the generation timeout for generation and retain the short timeout for health checks. This applies to the legacy endpoint adapter; it is separate from the Codex SDK transport used by the newer structured operations.

10. **[P2] Ingestion telemetry cannot currently establish cache savings or reliably account for interrupted paid work.** [usage.py:33](/home/saturn/Documents/thinking/learnanything/src/learnloop/ai/usage.py:33), [usage.py:136](/home/saturn/Documents/thinking/learnanything/src/learnloop/ai/usage.py:136), [source_unit_inventory.py:678](/home/saturn/Documents/thinking/learnanything/src/learnloop/content/synthesis/source_unit_inventory.py:678). The transport accumulator retains only input/output totals and calls. Cache read/write details, provider request IDs, resolved endpoint/model, finish reason, and reported cost are discarded. Inventory records estimated tokens and logical window calls without draining actual provider usage. The partial-inventory failure above persisted no job usage. Synthesis does preserve aggregate usage on handled failure, which is good, but an abrupt process loss before the drain loses its in-memory accounting; shard checkpoints do not include their call receipts. Failed synthesis job DTOs can also miss usage stored at the agent-run layer because the handler copies it only on success. Persist response-level usage with each checkpoint and derive job aggregates idempotently. Unknown usage must remain distinguishable from zero-cost reuse. OpenRouter exposes cache-read/write metrics that can support this measurement. [OpenRouter cache accounting](https://openrouter.ai/docs/guides/best-practices/prompt-caching).

**Retry policy that preserves tokens and the intended session**

Treat a frontend disconnect as a detach from the worker. Persist workflow, job, attempt-generation, request, and checkpoint identities. On reattachment, read progress and observe the existing owner while its lease is valid. Reclaim a dead owner's work conditionally; preserve completed artifacts. Use explicit user cancellation to stop scheduling more work and interrupt active provider turns where supported.

For stronger debug-session continuity, a long-lived worker per vault with reconnectable IPC would fit the intent better than relying on whichever descendants happen to survive. This is an architectural option, not a prerequisite for the smaller lease/checkpoint fixes. The current Python drain threads are daemon threads, so process survival alone is not a durable execution contract. The Codex app-server protocol exposes thread resume and turn lifecycle operations; evaluate those through the pinned SDK and persist their identities before adopting reconnection. [Codex app-server lifecycle](https://learn.chatgpt.com/docs/app-server#lifecycle-overview).

| Failure | Recommended next action |
| --- | --- |
| Retryable rate limit or temporary provider unavailability | Retry the same missing call under one bounded backoff/deadline policy; leave completed calls cached |
| Authentication, insufficient credit, unsupported request shape | Preserve checkpoints, record an actionable failure, and resume after the configuration/account condition changes |
| Connection loss or timeout after submission | Record an unknown outcome; use a persisted provider turn/request identity to recover status or output where supported before replaying |
| Truncated output | Preserve the fragment; adjust output allowance or split the work using semantic boundaries |
| Invalid JSON with recoverable content | One bounded repair using the saved response, with the reason and repair lineage recorded |
| Gate rejection or local apply failure | Repair/revalidate/apply the saved candidate; do not repeat valid generation |

Provider generation cannot generally be made exactly-once merely by adding a local request ID. Where result retrieval is unavailable, record the ambiguity and possible duplicate spend honestly. Local publication and usage aggregation can still be idempotent.

**Performance changes with the best expected return**

1. **Persist model-call results before expanding concurrency.** Reuse the existing SQLite writer on the runner thread, fed by a completion queue from provider workers. Add window and evidence-pass checkpoints alongside unit/shard checkpoints. This prevents the measured three-call replay after a single unit failure and releases result memory earlier. Replace static round-robin lane assignment with a bounded work queue when units vary greatly in size. Retain one client per worker and stop starting new calls after failure; benchmark concurrency against rate limits and time to the first usable section.

2. **Put stable task instructions before changing context.** [transport.py:180](/home/saturn/Documents/thinking/learnanything/src/learnloop/ai/transport.py:180) serializes the outer payload with `sort_keys=True`, putting `context` before `task`. In the inventory probe, two prompts shared only 299 initial application-prompt characters, while the common 2,251-character task appeared after the changing fields. Render a deliberately ordered envelope: stable instructions and schema, stable source-set context, then the changing unit/window and evidence follow-up. Keep deterministic serialization inside each section. Version the prompt change and check output quality. OpenAI documents cache reuse in terms of matching rendered prefixes; this observation does not establish zero existing cache hits because provider-added instructions/schema may still share a prefix. [OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching).

3. **Expose provider cache affinity and measure it.** For OpenRouter, consider a stable workflow-scoped `session_id`, since its default conversation key incorporates the first user message, which currently changes between units. Use provider-supported cache controls at the end of reusable content where required. Routing affinity and cache hits remain best-effort, and behavior varies by model/provider. Measure actual cached tokens, writes, cost, and latency before making stronger routing restrictions. [OpenRouter prompt caching](https://openrouter.ai/docs/guides/best-practices/prompt-caching).

4. **Remove the redundant v2-lite extraction.** [jobs.py:1684](/home/saturn/Documents/thinking/learnanything/src/learnloop/content/pipeline/jobs.py:1684) explicitly intends to use already extracted IR, but the called service fetches and normalizes the source first. Build that handoff from the stored revision metadata, original artifact reference, and selected IR. Preserve an explicit source-refresh operation. A deliberate refresh and a retry of an already imported revision should have different execution paths.

5. **Amortize Codex app-server startup without growing an unbounded conversation.** Measure startup separately from inference, then consider keeping one app-server connection alive per provider lane. Resume a thread for the same in-flight logical operation when appropriate; unrelated units can still use isolated threads. Fresh threads do not necessarily prevent provider prefix caching. If threads are reused, change the current cumulative-thread token accounting to per-turn deltas: [usage.py:159](/home/saturn/Documents/thinking/learnanything/src/learnloop/ai/usage.py:159) explicitly relies on every structured call starting a fresh thread.

The relevant comparison is cost and latency per accepted, usable source unit or study map, including failures and repairs. Smaller windows improve retry granularity but repeat instructions and can lose cross-unit coherence; larger windows amortize context but increase output-size and failure exposure. Keep selected-span provenance, held-out exam separation, and the cross-shard graph pass. Sweep a few bounded window/concurrency choices on representative sources, measuring gate acceptance, coverage, user edits, cached tokens, total spend, and time to first usable content. Cache discounts should not justify sending irrelevant source text or delaying useful parallel work for a speculative cache hit.

**Telemetry and the future learned dataset**

`state.sqlite` remains an appropriate home for local call receipts and checkpoint metadata. The immediate architectural problem is incomplete event identity and durability, not SQLite itself. Extend the existing persistence seam so saving a response/checkpoint and its usage is atomic, with short transactions. A provider worker should send completed results to the writer rather than hold a database transaction open during inference. Large immutable response/source artifacts can remain in the file store under content hashes.

Each call receipt should retain the workflow/job/attempt generation; stage and unit/window/pass; frozen request and prompt/schema versions; requested and resolved provider/model; provider request or Codex thread/turn IDs where available; timestamps and outcome classification; output hash and validation disposition; retry/repair lineage; input/output/cache-read/cache-write/reasoning counters when supplied; and cost with an explicit reported/estimated/unknown basis. Keep complete, failed, rejected, repaired, and unknown outcomes distinguishable. Compute aggregates from receipts without counting a cache hit as another generation or charging cumulative thread usage twice.

Connect those receipts through source revision and spans to inventories, candidates, gate decisions, accepted proposals, user edits, and downstream reader/practice outcomes. That supplies evidence for learned chunking, provider selection, repair, and source-scope policies. A schema-valid output is not a learning-outcome label. The original review's offer-attribution and outcome-eligibility findings still need fixing before downstream outcomes become reliable supervision. Preserve the raw evidence and version derived labels so future models can learn from failures and corrections as well as accepted content.
